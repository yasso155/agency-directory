# بوت التغذيات (واتساب)

يشتغل بجانب صفحة دليل الوكالات. لما الموظف يضغط **"تمت التغذية، أرسل للجروب"** في الصفحة، الصفحة بتكتب سجل في Firestore بحالة `pending`. البوت بيشوفه فوراً، يرسل الرسالة للجروب من الرقم المخصص، ويحدّث الحالة إلى `sent` (أو `failed` مع سبب الفشل).

```
الصفحة (Vercel) ──يكتب──▶ Firestore: topups  ◀──يستمع ويحدّث── البوت (VPS) ──▶ جروب واتساب
```

البوت ما بيقرا رسائل الجروب ولا الإيصالات. بس بيرسل.

## قبل البداية

- **رقم مخصص للبوت** (شريحة منفصلة، مو رقمك الشخصي)، مسجّل في واتساب على تلفون، ومضاف لجروب الإيصالات.
- **جروب تجريبي أول:** أنشئ جروب فيه أنت والرقم المخصص بس، وجرّب عليه قبل ما تحط الجروب الحقيقي.
- **سيرفر يشتغل طول الوقت** (VPS صغير أي مزوّد، أو أي منصة تحفظ مجلد `auth/` بشكل دائم). ما بيشتغل على Vercel.
- **Node 20.6 أو أحدث.**

## الإعداد

**1) مفتاح Firebase**
Firebase Console ← Project settings ← Service accounts ← **Generate new private key**. احفظ الملف باسم `serviceAccount.json` داخل مجلد `agency-bot/`. ما ترفعه لـ GitHub ولا Vercel، فيه صلاحيات كاملة على مشروعك.

**2) التثبيت**
```bash
cd agency-bot
npm install
cp .env.example .env
```

**3) ربط رقم البوت**
في `.env` اكتب `PAIRING_PHONE` برقم البوت بالصيغة الدولية بدون `+` (مثلاً `9665XXXXXXXX`)، وبعدين:
```bash
npm run groups
```
بيطلع **كود ربط** من 8 خانات. على تلفون رقم البوت: واتساب ← الأجهزة المرتبطة ← ربط جهاز ← **الربط برقم الهاتف بدلاً من ذلك** ← اكتب الكود. (لو خليت `PAIRING_PHONE` فاضي بيطلع QR بدل الكود.)

بعد الربط بيطبع قائمة الجروبات اللي الرقم عضو فيها. انسخ الـ ID (ينتهي بـ `@g.us`) للجروب التجريبي وحطه في `GROUP_JID` داخل `.env`.

**4) التشغيل**
```bash
npm start
```
لازم تشوف: `واتساب متصل` ثم `البوت شغال، بانتظار التغذيات…`. افتح الصفحة، سوّي تغذية تجريبية، وتأكد إن الرسالة وصلت الجروب التجريبي والحالة في السجل صارت "أُرسلت للجروب".

**5) النقل للجروب الحقيقي**
غيّر `GROUP_JID` لجروب الإيصالات (من `npm run groups` تاني)، وأعد تشغيل البوت.

**6) يشتغل دايماً**
```bash
npm i -g pm2
pm2 start npm --name agency-bot -- start
pm2 save
pm2 startup      # ينفّذ الأمر اللي يطلعه عشان يرجع البوت بعد إعادة تشغيل السيرفر
```

## كيف يتصرف

- **منع التكرار:** كل رسالة بيحجزها البوت داخل transaction قبل الإرسال، فما تنرسل مرتين حتى لو شغلت نسختين بالغلط.
- **لو البوت وقع وسط الإرسال:** الرسالة بتتعلّم `failed` برسالة "تأكد من الجروب قبل إعادة المحاولة"، لأن ممكن تكون وصلت. الموظف يقرر.
- **لو واتساب أو البوت انقطع:** الرسائل بتفضل `pending` وبتنرسل بالترتيب لما يرجع. والصفحة بتعرض تنبيه أصفر، وفي السجل زر "نسخ الرسالة" لو عايز ترسلها يدوي.
- **النبض:** البوت يكتب `system/bot` كل دقيقة، والصفحة تعتبره منقطع بعد 3 دقايق.
- **سرعة الإرسال:** رسالة واحدة بعد كل تغذية مع تأخير عشوائي 1 إلى 3 ثواني. ما فيه إرسال جماعي.

## ملاحظات مهمة

- المكتبة (Baileys) **غير رسمية**. استخدام واتساب بهذا الشكل ضد شروطهم نظرياً، وفيه احتمال حظر الرقم. لذلك رقم مخصص ورسائل قليلة ومرتبطة بعملية فعلية.
- **تلفون رقم البوت** لازم يفتح واتساب مرة كل أسبوعين تقريباً، وإلا الأجهزة المرتبطة بتتسجل خروجها.
- لو سُجّل خروج الجهاز: احذف مجلد `auth/` وأعد الخطوة 3.
- لو الربط فشل بعد التثبيت بأخطاء اتصال، جرّب الإصدار القديم: `npm i @whiskeysockets/baileys@6.7.24` (الكود يشتغل معه).
- نص الرسالة نفسه بيتبنى في الصفحة (`buildMessage` أعلى `app.js`)، والبوت يرسل أي نص مكتوب في حقل `message`.
